## 2. 사용자가 확정한 화면과 기능 요구

1. 첫 화면을 **목표 물질 → 생성 엔진 → 경로 생성** 중심으로 간결하게 만든다.
2. **경로 업로드, JSON 직접 편집, 저장 경로 및 가상 예시 불러오기 입력 섹션을 완전히 제거**한다. 고급 설정에 접어 숨기는 것으로 대신하지 않는다.
3. JSON은 내부 처리와 선택적인 결과 다운로드에만 남길 수 있다. 기존 연구 JSON 파일은 삭제하지 않는다.
4. 생성 결과를 기존 네 검토 영역인 위험 검토·투입량·부산물·비용으로 자동 연결한다. 생성 전이나 전부 제외 상태에서 빈 계산 패널을 나열하지 않는다.
5. 우려 물질/신호가 있는 경로는 기본 제시 목록에서 제외한다. **「제외된 경로와 이유 (N)」**를 펼치면 어떤 경로의 어느 단계에서 어떤 물질이 왜 문제인지 모두 확인할 수 있어야 한다.
6. 구조 경보와 모델 양성을 확정 독성으로 단정하지 않는다. 표시 문구는 ‘우려 신호로 제외’ 등으로 근거 종류를 구분한다.
7. 정보 부족·미평가·실패·미검출은 안전 판정이 아니다. 전부 제외되면 ‘제시 가능한 경로 없음’을 보여주고 다른 결과로 몰래 대체하지 않는다.
8. SynthEx를 선택할 때만 개인 Gemini API 키 입력, 키 삭제, 외부 전송·과금 동의가 나타나게 한다. Gemini 앱 구독과 API 이용은 별개다.
9. 독립 물질 검사 기능은 간결한 별도 진입점으로 유지한다. 목표물 자체는 불순물 집계에서 제외하지만 독립 검사할 수 있다.
10. 이미 수정한 하늘색 선택 컨트롤과 넓어진 데스크톱 화면을 유지한다. 이 작업은 다시 하지 않는다.

## 7. 새 코드의 핵심 API — UI 연결에 사용

### GenerationService
`app/generation_service.py`, 세션별 인스턴스만 사용:

```python
GenerationService(config_path=None)
readiness(engine)
start_readiness(engine, *, request_id, context_id)
start(engine, target, *, request_id, context_id, configuration_id, gemini_api_key=None)
poll(request_id, *, context_id=None)
cancel(request_id)
close()
```

- engine: `aizynthfinder` / `synthex`
- readiness는 파일/설정 확인이며 실행 성공이 아니다. 비동기 key-free probe가 완료돼야 `ready=True`와 `configuration_id`를 얻는다.
- 동의에 configuration_id까지 묶고 start에 반드시 전달한다. 설정 변경을 실행 전/결과 적용 전에 검사한다.
- 상태: queued/running/cancelling/succeeded/partial/failed/cancelled/timed_out/bounds_exceeded. 문맥 불일치 poll은 stale 및 result=None.
- result: `{payload, provenance, artifacts, item_failures}`
- partial은 payload=None일 수도 있다. pre-stitch 경로나 저장 결과로 성공을 대체하지 않는다.
- 설정: `generation.local.json`의 schema_version='1.0', 각 engine.python 절대 경로, synthex.config 절대 경로. 키는 설정에 없다.
- worker는 `-I -B -X utf8`로 실행한다. `-I`에서는 PYTHONUTF8 환경변수만으로 UTF-8을 강제할 수 없다.
- 상한: AiZynth 탐색 30초/30회·전체 120초, SynthEx 전체 900초, 스트림당 1MiB, 요청 파일 합계 32MiB/100개. 시간 제한은 비용 상한이 아니다.

### workspace/AMES
```python
workspace.set_model_evidence(workspace, envelope)  # 새 상태 반환
workspace.current_model_evidence(workspace)
workspace.model_evidence_status(workspace)
workspace.eligible_routes(workspace)
```

- `eligible_routes`: 보고서 경로 사본, 원래 순서.

- `get_route_ames_evidence`의 envelope를 setter에 전달한다. show의 화면용 반환값이나 직접 dict 대입으로 대신하지 않는다.
- `report_generation`, `model_evidence_state`, `model_evidence_history`를 화면/내보내기 스냅샷에 포함한다.
- 과거 `_report_sha256`은 제거됐고 `workspace.report_hash`가 공통 함수다.

## 8. 지금 해결 중인 문제 — 중요

새 생성 경계 테스트를 실행한 결과:
- 46개 / 52.190초
- **실패 5개 + 오류 5개**
- full workflow, partial handling, manifest validation 테스트가 주로 막혔다.

확인한 원인:
원본 `synthex/src/synthex/artifacts.py`의 ArtifactStore.write_checkpoint는 UTF-8 LF 텍스트의 digest를 계산하지만 Path.write_text의 Windows 기본 줄바꿈 변환으로 파일은 CRLF가 된다. 따라서 원본 read_checkpoint도 digest mismatch로 거부한다. 일부 변조 subtest는 같은 immutable checkpoint 디렉터리도 재사용했다.

인계 직전 코드 확인:
- `app/generation_worker.py`에 `_ArtifactPath`, UTF-8/LF store adapter, 원본 artifacts/pipeline의 store 생성 경계에만 적용했다가 복구하는 코드가 이미 작성돼 있다.
- 전역 Path monkeypatch나 upstream 파일 수정 없이 원본 저장/검증 알고리즘을 유지하려는 수정이다.

## 9. 남은 작업 — 이 순서로 진행

1. 중단된 작업자의 마지막 변경과 실제 파일을 읽고 소유권을 정리한다. 동시에 같은 파일을 수정하지 않는다.

3. 두 엔진에 대해 **키 없는 준비 확인**을 실제 실행한다. 패키지/파일 존재와 준비 확인, 실제 실행 성공을 구분한다.

5. 승인된 한 번의 제한된 실제 로컬 AiZynthFinder 생성으로 목표→원본 실행→자동 선별→검토의 end-to-end를 검증한다. 기존 저장 결과를 새 생성으로 표시하지 않는다.
6. SynthEx는 오프라인 대역만 사용해 원본 CLI/full-stage 계약, stitching 추가 화학 반영, 종료 0이지만 불완전한 결과, 모든 경로/개별 실패 보존을 검증한다. 실제 Gemini 요청 금지.
7. 실제 브라우저에서 밝게/어둡게, 데스크톱/모바일, 키보드, 제외 상세, 키 입력/삭제, 세션 분리, 계산·가격·부산물 동의 무효화 및 내보내기를 확인한다. 가짜 키를 사용하며 실제 키를 캡처하지 않는다.
8. 소스가 안정된 뒤 전체 회귀 테스트를 수행한다. 실패·경고·변경 중 실행을 숨기지 않는다.
9. 소프트웨어가 확정된 뒤 아래 두 Word 문서를 작성하고 내용·링크·페이지 렌더링을 확인한다.
10. 최종 현재 소스로 독립 검토와 완료 감사를 수행한다. GJC ultragoal이면 frozen sourceHash 기반 cleaner/architect/QA를 합류한 뒤 수정하고, terminal critic 및 품질 게이트를 거쳐 완료한다. 과거 리뷰를 재사용해 새 코드를 승인하지 않는다.
