## 1. 프로젝트 배경

신약 개발에서 임상시험 단계까지 도달한 화합물이 최종 승인에 이르는 비율은 매우 낮으며, 그중에서도 항암제는 전체 치료 분야 가운데 승인률이 가장 낮은 영역이다. MIT 연구진이 2000년부터 2015년까지 40만여 건의 임상시험과 2만여 개의 화합물을 분석한 결과, 전체 평균 승인 확률은 13.8%였던 반면 항암제는 3.4%에 불과했으며, 다른 문헌들도 대체로 3.4~5% 범위로 보고하고 있다. 이는 곧 “임상에서 실패한 화합물”이라는 자원이 항암제 영역에서 가장 크고 의미 있게 축적되어 있다는 뜻이다.

기존의 리드 최적화 자동화 연구들은 대부분 “특정 물성을 개선하라”는 명확한 목표가 이미 주어진 상태에서 출발한다. 그러나 실제 현장에서 마주하는 상황은 그렇지 않은 경우가 많다. 어떤 화합물이 임상에서 실패했다는 사실만 알려져 있을 뿐, **무엇이 문제였는지조차 명확하지 않은 상태에서 원인 규명부터 시작**해야 하는 것이다. CURE는 바로 이 지점, 즉 개선 목표조차 정해지지 않은 출발선에서 **원인 진단부터 자동으로 수행한다**는 점에서 기존 연구들과 출발선이 다르다.

## 2. 모델 개요

**CURE(Clinical-failure Understanding & Redesign Engine)는 임상시험 단계에서 실패했거나 시장에서 철수된 화합물을 입력 받아, 그 실패 원인을 독성·효력·물성 세 축에서 스스로 진단하고, 진단된 원인과 연관된 구조 부위를 찾아 화학구조를 반복적으로 조정함으로써 개선된 후보 화합물을 제안하는 멀티에이전트 파이프라인이다.** 구조 조정은 Matched Molecular Pair Analysis(MMPA)를 기반으로 하는데, MMPA란 구조가 한 곳만 다른 화합물 쌍을 비교하여 어떤 구조 변화가 어떤 물성·독성·효력 변화를 일으키는지 통계적으로 추출하는 기법이다.

파이프라인은 **타겟 자동탐색 단계를 포함해 총 8단계, 8개의 Agent**로 구성되며 두 개의 피드백 루프를 갖는다. 하나는 진단한 문제가 실제로 해결되었는지를 확인하는 내부 루프이고, 다른 하나는 재설계 과정에서 새로운 임상 실패 패턴에 걸리지 않았는지를 확인하는 외부 루프이다. 이 이중 피드백 구조는 제약업계의 표준 리드 최적화 절차인 DMTA 사이클(Design–Make–Test–Analyze)을 그대로 자동화한 것으로 해석할 수 있다. 즉 새로 발명한 임의의 워크플로가 아니라 현장 관행을 자동화한 것이기 때문에, 설계의 정당성이 이미 업계 표준으로 확보되어 있다는 강점을 갖는다.

CURE는 ChEMBL, PubMed, ClinicalTrials.gov 등에 이미 축적된 구조·물성·효력 관계와 임상 실패 선례, 그리고 ADMETLab 같은 공개 독성 예측 도구를 자동으로 조회하고 활용한다. 이를 통해 의약화학자가 수작업으로 수행하던 실패 원인 진단, 구조 재설계, 재검증의 반복 과정을 에이전트가 체계적으로 보조한다.

### **2.1 용어 빠른 참조**

| 용어 | 뜻 |
| --- | --- |
| SMILES | 화학 구조를 문자열 하나로 표현하는 표기법으로, 모든 Agent의 기본 입출력 형식이다 |
| 스캐폴드(scaffold) | 활성에 핵심적인 중심 골격을 가리키며, Murcko scaffold 정의와 RDKit으로 자동 분리한다 |
| RDKit descriptor | 구조식만으로 계산 가능한 물성 수치(logP, TPSA, 분자량 등)를 통칭한다 |
| 타겟(target) | 화합물이 결합해 작용하는 대상 단백질을 말한다 |
| 효력(potency) | 타겟에 얼마나 강하게 작용하는지를 IC50, Ki 등으로 나타낸 지표이다 |
| MMPA | 한 곳만 다른 화합물 쌍을 비교해 구조 변화의 효과를 통계적으로 추출하는 기법이다 |
| Tanimoto 유사도 | 두 화합물의 구조 유사성을 0~1로 나타내는 지표이다 |
| Agent | 상태를 스스로 판단해 다음 행동을 결정하는 소프트웨어 단위이며, 여럿이 협업하면 멀티에이전트이다 |
| MCP | LLM(에이전트)이 외부 도구를 일관된 방식으로 호출하게 해주는 표준 연결 규격이다 |

## 3. 대상 범위와 입력 데이터

### 3.1 항암제로의 범위 한정

초기 기획안은 전체 질환의 철수·중단 화합물을 대상으로 삼았으나, 팀 회의를 거쳐 대상 질환을 **항암제(oncology)로 한정하는 방안**을 고려 중이다. 항암제가 임상 실패율이 가장 높아 대상 풀이 가장 크고, 타겟 범주 또한 키나아제·면역관문억제제·호르몬수용체 등으로 비교적 잘 정리되어 있어 타겟 자동탐색의 성공률이 높을 것으로 기대되기 때문이다.

이에 따라 주력 입력 데이터도 초기의 WITHDRAWN 데이터베이스에서 **ClinicalTrials.gov 직접 조회**로 전환하였다.

### 3.2 입력 데이터 파이프라인

ClinicalTrials.gov에서 암 관련 종료 시험을 조회한 뒤 **약물 성분이 있는 것만 골라 그 구조식(SMILES)을 확보**하는 과정이며, 실행 결과는 다음과 같다.

| 단계 | 내용 | 실행 결과 |
| --- | --- | --- |
| ① 조회 | 암 관련(query.cond=cancer) + 종료(overallStatus=TERMINATED) 시험 조회 | **11,032건** |
| ② 필터링 | 약물 개입(intervention type = DRUG) 시험만 남김 | **7,801건** |
| ③ 구조식 확보 | 약물명을 ChEMBL/PubChem에서 검색해 SMILES로 변환 (진행 중) | 약물명 2,419개 대상, 진행률 약 40% |
| ④ 최종 확정 | SMILES가 확보된 것만 최종 입력 목록으로 사용 | 진행 예정 |

### 3.3 입력 데이터 전처리 규칙

파이프라인을 실제로 실행하는 과정에서 발견될 여러 문제를 대비하기 위해, 입력 데이터에 대하여 다음과 같은 전처리 규칙을 설립하였다.

- 병용요법(한 시험에 약물이 2개 이상)은 제외하고 **단일 약물 시험만 사용**한다.
- 약물명에 붙은 용량·단위(예: “Crizotinib 250 MG”)는 제거한다.
- 대소문자를 통일해 중복을 제거한다.
- **항체 기반 약물(성분명이 “-mab”으로 끝나는 것)은 제외**한다. 저분자가 아니므로 SMILES로 표현할 수 없고, MMPA 기반의 Agent 2·3도 저분자를 전제로 하기 때문이다. PubChem 매핑 실패 사례의 상당수가 이 경우로 추정된다.
- 상품명(브랜드명) 표기는 매핑에 실패하면 별도 확인 대상으로 분류한다.

### 3.4 효력 실패 케이스 보완 (COMPLETED 경로 추가)

기존 파이프라인은 조기 중단(TERMINATED) 시험만 조회했는데, 이 상태는 대부분 안전성 문제나 사업적 판단으로 중간에 멈춘 경우이다. 그러나 항암제 3상에서 가장 흔한 실패 유형은 시험이 끝까지 진행된 뒤(COMPLETED) 1차 종결점(전체생존율 등)이 대조군 대비 유의한 개선을 보이지 못하는 **효력 실패**이며, 이 유형이 기존 필터에서 체계적으로 누락되고 있었다. 이에 두 번째 입력 경로를 추가하기로 하였다.

| 경로 | 조회 조건 | 판별 방식 | 처리 난이도 |
| --- | --- | --- | --- |
| A (기존) | cancer + TERMINATED | 상태값 자체가 결과 표시이므로 필터 하나로 확정된다. | 낮음 |
| B (신규) | cancer + COMPLETED + hasResults=true | 시험마다 1차 종결점 p-value를 확인해 p>0.05 (효과 없음) 인 것만 효력 실패로 필터링한다. | 높음
(결과지
개별 확인) |

경로 B가 어려운 이유는, **끝까지 진행되었다는 사실만으로는 성공인지 실패인지 알 수 없어 시험마다 결과 페이지를 열어 통계적 유의성을 직접 확인**해야 하기 때문이다. 실제 조사에 따르면 결과 페이지 중 p-value가 명확히 기재된 경우는 절반뿐이고 나머지는 원자료로 직접 계산해야 하며 그중 일부는 계산조차 불가능하다. 다만 ClinicalTrials.gov API v2의 `resultsSection` 필드로 접근이 가능함을 확인했고, **Duke대·FDA가 공동 운영하는 AACT 데이터베이스를 활용**하면 개별 API 파싱보다 효율적일 수 있어 이를 함께 검토하고 있다.

## 4. 전체 파이프라인

여덟 개의 Agent가 순차적으로 작동하되, 두 개의 피드백 루프가 반복 개선을 담당한다. 내부 루프는 Agent 4에서 기준 미달 시 Agent 3으로 되돌아가는 경로(최대 5회, 자가 재검토 1회 포함)이고, 외부 루프는 Agent 6에서 신규 실패 위험이 발견되면 Agent 3으로 되돌아가는 경로(최대 3회)이다.

```
[0] 타겟 자동탐색
        │
        ▼
[1] 진단 (독성·물성·효력)
        │
        ▼
[2] 문제 부위 탐지 ◄─────────┐ (후보 없음, 1회 재검토)
        │                    │
        ▼                    │
[3] 구조 변형 제안 ──────────┘
        │       ▲          ▲
        ▼       │          │
[4] 재평가 ─────┘ 기준 미달  │ (내부 루프, 최대 5회)
        │ 기준 통과          │
        ▼                    │
[5] 최종 후보 랭킹           │
        │                    │
        ▼                    │
[6] 신규 실패 위험 체크 ──────┘ (외부 루프, 최대 3회 / 선택 사항)
        │ 문제 없음
        ▼
[7] 최종 리포트
```

## 5. 에이전트 설계 상세

각 Agent의 역할, 입출력, 사용 도구, 우선순위를 정리하면 다음과 같다. 우선순위는 항암제 한정 이후 조정된 것으로, Agent 6(신규 실패 위험 체크)만 선택 사항이고 나머지는 모두 필수이다.

| Agent | 역할 | 입력 → 출력 | 주요 도구 | 우선순위 |
| --- | --- | --- | --- | --- |
| **0. 타겟 자동탐색** | 화합물이 노리는 단백질 타겟을 확인하고, 원래 시험의 암종과 관련 있는 타겟인지 교차검증한다 | SMILES·화합물명 
→ 타겟 ID·타겟명·신뢰도 | ChEMBL(drug_mechanism), PubMed 폴백 | 필수 |
| **1. 진단** | 독성·물성·효력 세 축을 진단해 기준 미달 항목을 가려낸다 | SMILES·타겟 정보 
→ 축별 수치·문제 축 리스트 | RDKit, ADMETLab 3.0, ChEMBL | 필수 |
| **2. 문제 부위 탐지** | 문제 축과 통계적으로 연관된 부분구조를 특정한다 | SMILES·문제 축 
→ 문제 부분구조·mmpdb DB | ChEMBL, RDKit, mmpdb | 필수 |
| **3. 구조 변형 제안** | 스캐폴드는 유지한 채 문제 부위의 치환 후보를 생성한다 | SMILES·문제 부위 
→ 변형 후보 리스트 | RDKit, mmpdb(transform) | 필수 |
| **4. 재평가** | 변형 후보를 재진단하고 다중목적(Pareto)으로 판정한다 | 변형 후보 
→ 축별·종합 통과 여부 | (7장 참조: 독립 도구) | 필수 |
| **5. 최종 후보 랭킹** | 통과 후보를 개선도 순으로 정렬한다 | 통과 후보 
→ 랭킹 테이블 | pandas | 필수 |
| **6. 신규 실패 위험 체크** | 재설계 후보가 새로운 실패 패턴을 밟지 않는지 확인한다 | 상위 후보 
→ 리스크 판정 | WITHDRAWN, ChEMBL(drug_warning), ClinicalTrials | *선택* |
| **7. 최종 리포트** | 전체 실행 경로와 근거를 종합해 리포트를 생성한다 | 전체 로그 
→ 마크다운·JSON 리포트 | — | 필수 |

### 주요 Agent별 보충 설명

**Agent 0 (타겟 자동탐색)** 은 효력 진단의 전제가 되므로 진단보다 먼저 실행된다. ChEMBL의 `drug_mechanism` 테이블에서 1차로 조회하고, 없으면 PubMed 문헌을 검색해 LLM이 타겟명을 추출한 뒤 ChEMBL의 `target_dictionary`로 실재 여부를 검증한다. 항암제 한정 이후에는 타겟이 잘 정리되어 있어 문헌 폴백으로 넘어가는 비율이 낮아질 것으로 예상한다. 여기에 더해, 찾아낸 타겟이 원래 시험의 조건(예: “Breast Cancer”)과 실제로 관련 있는지 교차검증하는 단계를 추가하였다. 만약 유방암 시험인데 백혈병 특이적 타겟이 잡히는 식으로 어긋나면 신뢰도를 “잠정”으로 낮추고 리포트에 표시한다.

**Agent 1 (진단)** 은 독성 진단을 ADMETLab 3.0 호출 하나로 처리한다. ADMETLab 3.0은 hERG·간독성을 포함해 약 60개 안팎의 독성·ADMET 항목을 한 번에 예측하며(벤치마크 AUC 0.72~0.99), 따라서 진단 범위가 특정 항목 몇 개로 제한되지 않고 이 도구가 커버하는 범위 전체가 대상이 된다. 골수억제(혈액독성)는 항암제의 대표 부작용이지만 구조 기반 도구로는 예측이 어렵고 대부분 환자 임상데이터 기반으로 연구되어 있어, 이번 범위에서는 제외하고 확장 과제로 남긴다.

**Agent 2·3 (문제 부위 탐지·구조 변형)** 은 Agent 2가 구축한 mmpdb 데이터베이스를 공유한다. Agent 3이 내부 루프 상한에 도달해도 개선되지 않으면, 애초에 지목한 문제 부위 자체가 잘못되었을 가능성을 재검토하는 자가 재검토 루프를 한 차례 거친다.

## 6. 판정 기준

각 진단 축의 판정 기준은 별도 학습 없이 이미 확립된 표준 기준을 채택하는 것으로 확정하였다. 특히 초기 기획안의 “PK 축”은 실제 약동학 지표를 확보하기가 어렵다는 판단에 따라 **“물성 축”으로 이름과 내용을 수정**하였다.

| 기존 축 | 명칭 (수정) | 판정 도구 | 문제로 판정하는 기준 |
| --- | --- | --- | --- |
| 독성 | 독성 축 | Agent 1: ADMETLab 3.0 Agent 4: 독립 도구(7장) | Agent 1은 위험도 점수 0.7 초과
Agent 4는 별도 기준(7장) |
| PK | 물성 축 | RDKit (logP, TPSA, 분자량) | Lipinski’s Rule of Five를 벗어남 
(logP>5, MW>500, TPSA≥140) |
| 효력 | 효력 축 | ChEMBL 상대 순위 | 같은 타겟 화합물들의 IC50/Ki 분포 대비 하위 25% |

독성 축의 진단 단계 위험도 점수는 0.7 초과를 고위험, 0.3~0.7을 중위험, 0.3 미만을 저위험으로 구간을 나눈다. Agent 4의 다중목적(Pareto) 판정은 “나빠졌다”를 이 위험도 구간이 더 나쁜 쪽으로 이동했는지(예: 저위험→중위험)로 정의하며, 모든 축에서 구간이 나빠지지 않은 후보만 통과시킨다.

### 조직특이적 분포(Kpu/Kp) 보완의 미채택

물성 축과 관련해 팀원(세희언니)이 제안한 조직특이적 분포 예측(Rodgers-Rowland 방정식 등)을 검토했으나 이번 1차 구현 범위에서는 채택하지 않기로 하였다. 대신 **분포(Distribution)는 ADMETLab 3.0이 제공하는 VDss(분포용적)로 확보**한다. 그 이유를 정리하면 다음과 같다.

| 검토 항목 | 판단 |
| --- | --- |
| 화합물 분류 부담 | 산성/염기성/양쪽성이온 등으로 나눠 서로 다른 식을 적용해야 해 복잡도가 늘어난다 |
| 방법론을 바꿔도 남는 병목 | ML/QSAR이든 외부 소프트웨어 호출이든, pKa/fu 확보와 13개 조직-암종 매핑이라는 근본 병목은 그대로 남는다 |
| 투입 대비 효과 | 위 병목이 해소되지 않는 이상 구현 복잡도 대비 실질 개선 효과가 제한적이다 |
| 남는 트레이드오프 | VDss는 전신 단일 값이라 “어느 조직에 축적되는가”는 설명하지 못하며, 이는 확장 과제로 남긴다 |

## 7. 설계 진화 기록 — 순환 검증 문제와 Agent 4 독립화

이 장은 팀 피드백을 거치며 **Agent 4(재평가)의 설계**가 어떻게 바뀌어 왔는지를 그 근거와 함께 기록한 것이다. 결론이 하나로 확정되기보다 여러 대안이 검토·수정되어 온 과정 자체가 이 프로젝트의 방법론적 엄밀성을 보여주는 부분이므로, 두 방향과 그 트레이드 오프를 모두 남긴다.

### 7.1 문제 정의 — 순환 검증(circular validation)

초기 설계에서는 Agent 1(진단)과 Agent 4(재평가)가 똑같이 ADMETLab을 사용했다. 이 경우 Agent 3이 ADMETLab 점수를 개선하는 방향으로 구조를 바꾸고 Agent 4가 다시 같은 ADMETLab으로 확인하는 셈이어서, **“낸 문제를 스스로 채점”하는 순환 구조**가 된다. 이 문제의 근거로 두 편의 문헌을 든다.

| 근거 | 핵심 주장 | 출처 |
| --- | --- | --- |
| Goodhart’s Law | 예측기 점수를 올리도록 능동적으로 최적화하면, 최적화된 집단에서는 점수와 실제 값의 상관이 붕괴한다. 점수 함수에 ML 예측기가 포함될수록 이 gaming이 심해진다 | Manheim 2019; Renz et al. 2019 |
| 앙상블 오차 분해 | E = Ē − Ā에서 두 모델이 완전히 같으면 다양성 Ā=0이 되어 E=Ē, 즉 두 번 확인한 것이 한 번 확인한 것과 수학적으로 동일해진다 | Krogh 1994 |

여기서 E는 합의의 오차, Ē는 개별 모델의 평균 오차, Ā는 모델 간 예측 다양성(ambiguity)이다. 두 문헌을 종합하면, 진단기와 검증기가 같을 경우 무작위 오차는 상쇄되더라도 화학 공간의 특정 영역에 뭉쳐 있는 체계적 오차는 교정되지 않으며, **자기일관성이 정확성을 대체하는 문제가 발생**한다.

### 7.2 두 갈래의 해결 방향

문헌들이 제시한 처방은 공통적으로 **“Agent 1과 Agent 4를 서로 독립적인 도구로 분리한다”**는 것이다. Renz는 최적화에 쓴 점수(OS)가 아니라 **다른 데이터로 학습한 독립 모델(DCS)로 최종 판정할 것**을, Krogh는 **모델 간 다양성(Ā)을 최대화**할 것을, Manheim은 **여러 불완전한 지표를 함께 보아 서로의 빈틈을 메울 것**을 권한다. 이 방향을 CURE에 적용하는 과정에서 두 가지 구체안이 나왔다.

| 구분 | 방향 A (예빈언니_완성도 보완 자료) | 방향 B (재윤_선행연구 정리 자료) |
| --- | --- | --- |
| **Agent 4 재판정 도구** | ProTox-II (또는 ProTox 3.0) | DICTrank/DILIrank/DIRIL로 학습한 로컬 RF |
| **성격** | 다른 연구팀이 다른 방법론으로 만든 외부 예측 사이트 | 다른 데이터·다른 알고리즘으로 직접 학습한 DCS 모델 |
| **구현 난이도** | ADMETLab 호출과 동일한 수준 
(단, 자동 호출 API 유무 미확인) | 로컬 학습 필요하나 팀이 이미 DICT·DILI 모델 보유 |
| **공통 추가 게이트** | PAINS/Brenk 구조 경보
(RDKit FilterCatalog 내장, 학습 무관) | 동일 |

두 방향 모두 ADMETLab 점수는 참고용으로만 남기고 최종 통과 판정 근거로는 쓰지 않는다는 점, 그리고 규칙 기반의 PAINS/Brenk 구조 경보를 세 번째 독립 신호로 병행한다는 점은 동일하다. PAINS/Brenk는 학습 기반이 아니어서 다른 두 도구와 오차가 겹칠 가능성이 원천적으로 없다는 장점이 있다.

### 7.3 남겨진 한계 — “부분적으로만 독립적”

방향 A(ProTox-II)에 대해서는 이후 검토에서 중요한 한계가 지적되었다. 오차에는 특정 모델이 우연히 잘못 학습한 “모델 특이적 오차”와 **학습 데이터 자체에 사례가 부족한 “데이터 빈틈”**의 두 종류가 있는데, 방법론(아키텍처)을 바꾸면 전자는 교정되지만 같은 데이터를 쓴다면 후자는 여전히 교정되지 않는다. 그런데 확인 결과 ADMETLab과 ProTox-II 모두 hERG 학습에 ChEMBL을 사용하고 있었다(ProTox-II는 ChEMBL 유래 5,252개 화합물로 학습). **따라서 아키텍처는 다르더라도 hERG처럼 원천 데이터가 겹치는 항목에서는 두 도구가 같은 데이터 빈틈을 공유**할 수 있으며, 이런 항목에 대해서는 **“부분적으로만 독립적”** 이라고 표현하고 한계로 남기는 것이 정직하다. 방향 B(로컬 RF)는 학습 데이터 자체를 DICTrank/DILIrank/DIRIL로 달리 가져가므로 이 데이터 빈틈 문제에서 상대적으로 유리하다.

덧붙여 어느 방향을 택하든, Renz의 방법 자체가 gaming을 사후에 검출하는 것이지 원천적으로 막는 것은 아니라는 점을 문헌이 명시하고 있다. 즉 Agent 4의 독립화는 “이것은 진짜 개선이 아니다”를 사후에 걸러내는 수준의 안전장치이며, 이 한계도 함께 기록해 둔다.

## 9. 검증과 케이스 스터디

### 9.1 검증 구조와 그 한계

CURE는 모델을 새로 학습시키는 구조가 아니므로 별도의 라벨링된 검증 데이터셋이 필수는 아니며, **Agent 4가 진단한 문제를 재설계 후 재확인하는 구조 자체가 1차 검증 역할을 겸한다.** 다만 검증의 성격을 정확히 구분할 필요가 있다.

| 검증 대상 | 검증 방법 | 성격 |
| --- | --- | --- |
| Agent 1의 진단 
(“왜 실패했나”) | 문헌 사유 일치율, TrialBench 카테고리 일치율(N≈1,300) | 외부 데이터와 대조 가능 |
| Agent 3의 구조 변형 
(“재설계가 문제를 해결했나”) | Agent 4 재평가 | 내부적 — 예측 도구로 자체 확인 |

여기서 근본적 한계가 분명해진다. Agent 4의 재평가는 “CURE 내부 도구의 예측값이 좋아졌다”를 확인할 뿐이며, CURE가 만든 신규 분자가 실제 세상에서 안전하고 효과가 있을지는 검증하지 못한다. 그 분자는 세상에 존재한 적이 없어 비교할 실측 데이터가 없기 때문이다. **임상시험을 다시 하지 않는 이상 완전한 검증은 불가능**하며, 이 점은 명확한 한계로 인정한다. 대신 사람이 확인할 수 있는 것은 “이미 벌어진 역사”이고, 이를 다루는 것이 **케이스 스터디**이다.

### 9.2 케이스 스터디 방법론

케이스 스터디도 화합물을 CURE에 넣어 진단·재설계받는 과정 자체는 메인 파이프라인과 완전히 동일하다. 차이는 **그 화합물이 실패한 이후 실제로 무슨 일이 있었는지를 사람이 추가로 조사한다**는 것뿐이다. 이 정보는 구조화된 DB에 없고 문헌에 흩어진 서술형 정보라 사람이 읽고 정리해야 하므로, 별도의 검증 Agent를 새로 만들 필요 없이 완성된 CURE를 그대로 재사용한다. 진행 순서는 **후보 화합물 선정 → CURE 실행·결과 기록 → 실제 이후 역사 문헌 조사 → CURE 결과와 실제 역사 비교**의 순이다.

후보 화합물은 문헌에 이미 정리된 3상 실패 항암제 목록(약 42건)을 1차 색인으로, 팀원의 PubMed 추가 검색을 2차로 활용해 발굴하며, 이 목록은 근거가 아니라 어떤 화합물을 조사할지에 대한 후보 색인으로만 사용한다.

### 9.3 케이스 스터디 결과의 정량화 (3단 지표)

기존의 “결과와 실제 역사를 비교해 스토리를 쓴다”는 방식은 사람의 주관적 판단에 기대므로, 여기에 **정량적 근거를 붙이기 위해 세 가지 지표를 함께 사용**한다.

| 지표 | 보는 것 | 필요한 이유 |
| --- | --- | --- |
| **2-1. 전체 Tanimoto 유사도** | CURE 후보와 실제 후속 화합물이 얼마나 닮았는가 | 서술형 스토리 대신 숫자 근거를 확보한다 |
| **2-2. 변형 부위(치환 규칙) 단위 비교** | CURE의 판단 과정 자체가 옳았는가 | Agent 3이 스캐폴드를 고정하므로 2-1만으로는
 “우연한 유사”와 “옳은 판단”을 구별하지 못한다 |
| **2-3. 근접 유사체 실측값 대조(read-across)** | 제안된 치환 규칙이 통계적으로 타당한가 | MMPA의 통계적 전제 자체를 독립적으로 재확인한다 |

2-3에는 주의점이 있다. **CURE가 만든 분자 X′와 구조적으로 아주 가깝지만(Tanimoto 0.9 이상) 계보상 무관하게 독립적으로 존재하는 화합물 Y의 실측값과 대조해야 하며, 이를 원본 X와 X′ 사이에 직접 적용해서는 안 된다.** CURE가 성공했다면 X와 X′는 구조는 비슷해도 물성은 크게 달라야 정상이기 때문이다(activity cliff — MMPA가 일부러 이용하는 현상). 후속 사례를 찾지 못하면 “확인 안 됨”으로 명시하고 억지로 스토리를 만들지 않는다.

### 9.4 특이도(위양성 방지) 확인

이미 승인된 항암제 중 조사 대상 실패 화합물과 같은 타겟을 공유하는 성공 사례를 짝지어 함께 수집한다. 짝을 찾지 못하면 단독 성공 사례를 CURE에 넣어 “심각한 문제 없음”으로 정상 판정하는지를 확인하며, 이를 통해 진단이 정상 화합물까지 과도하게 위험으로 판정하지 않는지를 점검한다.

## 10. 선행 연구 대비 차별화 지점

CURE의 핵심 방법론과 아키텍처는 여러 선행 연구에 뿌리를 두고 있으나, “임상 실패 원인의 자동 진단 → 구조 재설계 → 재검증”을 하나로 잇는다는 점에서 차별화된다.

| 선행 연구 | CURE와의 관계 | 우리 연구와의 차이점 |
| --- | --- | --- |
| MMPA 방법론
(Yang et al. 2023) | Agent 2·3의 핵심 로직, mmpdb로 바로 적용 | 방법론 자체만 다루고 **자동화·실패 진단**과 연결하지 않는다 |
| TxAgent 
(Gao et al. 2025) | 다도구 오케스트레이션 아키텍처가 동일 계열 | 치료 추천이 목적이고 **구조 재설계**는 다루지 않는다 |
| ToxMCP 
(Djidrovski 2026) | ADMETLab을 MCP로 연동, 감사 가능성 원칙 참고 | 독성 프로파일링 자체가 목적인 도구 모음이다 |
| 임상 실패 예측 ML 
(John et al. 2022) | 구조 기반 실패 예측, baseline·time-split 참고 | 성공/실패 예측에 그치고 **원인 특정·재설계**는 없다 |
| DILI 외부 검증 
(Mostafa et al. 2024) | 실제 실패 화합물로 외부 검증하는 설계 참고 | 간독성 단일 축, **구조 개선**은 없다 |
| 독성 기반 안전성 예측 
(Lysenko et al. 2018) | “전임상 통과 화합물은 구조 규칙으로 설명 어렵다”는 한계 근거 인용 | 예측 모델 자체가 목적이다 |
| AI Co-Scientist 
(Google DeepMind) | 사람이 지정 않은 방향을 스스로 발굴, 토너먼트 
랭킹은 Agent 5 참고, wet-lab 검증 선례 | 약물 재창출 가설 생성이 목적이고 **구조**는 건드리지 않는다 |
| DrugAgent 
(2025) | LLM 다중 에이전트 협업·지식그래프 결합 구조가 동일 계열 | DTI 예측 ML 프로그래밍 자동화에 국한된다 |

정리하면, CURE는 개선 목표가 주어지지 않은 상태에서 원인 진단부터 시작한다는 문제 설정, 그리고 진단·재설계·재검증을 DMTA 사이클로 자동화한 이중 루프 구조라는 두 축에서 기존 연구들과 구별된다.

## 11. 예상 결과물 및 연구 의의

### 11.1 예상 결과물

최종 결과물은 크게 세 가지이다. 첫째, **여덟 개 Agent로 구성된 실행 가능한 멀티에이전트 파이프라인** 자체이다. 둘째, **각 입력 화합물에 대해 Agent 7이 생성하는 리포트**인데, 여기에는 진단된 실패 원인, 재설계된 후보 구조, 개선도 랭킹, 그리고 내부·외부 루프의 반복 횟수와 자가 재검토 발생 여부 같은 실행 경로가 함께 담긴다. 최종 후보를 찾지 못한 경우(대체 골격 필요, 루프 상한 도달, 구조적 상충 관계)에도 반드시 리포트를 생성해 실패 자체와 그 이유를 명확히 전달하는 것을 종료 조건으로 삼는다. 셋째, **케이스 스터디 결과물**로서 과거 실패 항암제에 대한 CURE의 진단·재설계 결과를 실제 역사와 정량적으로 비교한 사례 모음이다.

### 11.2 연구 의의

CURE의 의의는 세 가지로 요약된다. 먼저 **시간과 비용의 절감**이다. 의약화학자가 여러 데이터베이스를 수작업으로 대조하던 진단·재설계 과정을 자동화된 조회와 검토로 단축하며, 특히 신규 실패 위험 체크는 개별 연구자가 놓치기 쉬운 과거 실패 사례를 체계적으로 확인해 반복될 수 있는 실패 비용을 조기에 방지한다. 다음으로 **일관성**이다. 수작업 검토는 검토자의 경험과 참고 문헌 범위에 따라 결과가 달라지지만, CURE는 동일한 기준을 모든 화합물에 일관되게 적용한다. 마지막으로 **실제 활용 가능성**이다. 제약회사가 임상 실패 화합물을 재활용해 후속 화합물(backup compound)을 개발하는 과정을 보조할 수 있고, 학술 연구실에서도 저비용으로 재설계 방향을 탐색할 수 있으며, MCP 기반 설계 덕분에 특정 벤더에 종속되지 않고 다른 도구로 손쉽게 교체·확장할 수 있다.

## 12. 한계

| 한계 | 내용 |
| --- | --- |
| **완전 검증 불가** | 신규 분자의 실제 안전성·효력은 임상을 다시 하지 않는 한 검증할 수 없다 (9.1 참조) |
| **데이터 규모 의존** | MMPA는 ChEMBL에 해당 타겟·스캐폴드 시리즈가 충분해야 유효하며, 신규성 높은 화합물·희귀 타겟에서는 제안 품질이 떨어진다 |
| **부분적 독립성** | Agent 1·4가 원천 데이터(예: hERG의 ChEMBL)를 공유하는 항목에서는 독립성이 부분적이다 (7.3 참조) |
| **gaming 사후 검출** | Agent 4의 독립화는 gaming을 원천 차단하지 못하고 사후에 걸러내는 안전장치이다 |
| **골수억제 미포함** | 항암제 주요 부작용이나 구조 기반 예측이 어려워 이번 범위에서 제외한다 |
| **스코프 한계** | 새로운 생물학 지식을 생성하지 않으며, 특이체질 반응 등 구조로 설명되지 않는 실패는 대상이 아니다 |
| **applicability domain** | ADMETLab 등 외부 예측 모델은 학습 화학공간을 벗어나면 신뢰도가 낮아지므로, 최종 판단은 사람 검토를 전제로 한다 |

또한 외부 자원 접근이 불가능할 경우에 대비해, ChEMBL은 전체 스냅샷을 로컬로 확보하고, ADMETLab 장애 시에는 자체 학습한 RF 로컬 모델로 대체하며, 발표 당일에는 검증용 화합물의 실행 결과를 미리 산출·캐싱해 시연하는 것을 원칙으로 삼는다.

## 13. 확장 방향성

현재의 1차 구현 범위를 넘어 다음과 같은 확장을 계획하고 있다.

- **조직특이적 분포 예측**: 모델 정교화 단계에서 pKa/fu 확보와 조직-암종 매핑 문제가 해결되면 Kp/Kpu 기반 조직특이적 분석을 도입해, VDss가 설명하지 못하는 “어느 조직에 축적되는가”를 보완한다.
- **골수억제(혈액독성) 축 추가**: 구조 기반 예측이 어려운 이 항암제 대표 부작용을, 환자 임상데이터 기반 모델을 결합하는 방식으로 확장 과제화한다.
- **효력 실패 경로(COMPLETED)의 완전 구현**: 현재 방법만 확인된 경로 B를 AACT DB 활용과 함께 코드화해 효력 실패 사례를 충분히 확보한다.
- **Agent 4 독립성 강화**: 원천 데이터가 겹치지 않는 독립 모델을 추가해 “부분적 독립”을 “완전 독립”에 가깝게 끌어올린다.
- **대상 질환 확대**: 항암제에서 검증된 파이프라인을 다른 치료 분야의 실패 화합물로 이식한다.
- **Agent 6(신규 실패 위험 체크)의 정식 편입**: 현재 선택 사항인 이 단계를 필수 경로로 승격해 외부 루프의 안전성 검증을 강화한다.
