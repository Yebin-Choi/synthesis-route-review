# ReRx

합성 경로를 찾고, 그 경로에 등장하는 물질이 유전독성 불순물인지 여러 도구로 함께 검토하는 연구용 소프트웨어입니다.

## 왜 도구가 여러 개인가

유전독성을 예측하는 방식이 도구마다 다릅니다. 어떤 도구는 변이원과 함께 나타나는 부분 구조 목록을 대조하고, 어떤 도구는 실측 자료로 학습한 통계 모델로 점수를 냅니다. 같은 물질을 두고 답이 갈리는 일이 흔합니다.

그래서 판정을 하나로 합치지 않았습니다. 자체 개발한 모델을 포함해 일곱 개 도구의 답을 나란히 놓고, 어디서 갈렸는지 보여줍니다. 결론은 보는 사람이 냅니다.

| 예측 방식 | 도구 |
|---|---|
| 부분 구조 대조 | ICH M7, Toxtree 3.1.0, OECD QSAR Toolbox 4.9 |
| 통계 모델 | 자체 모델 1과 2, ADMET-AI 2.0.1, EPA TEST 5.1.2 |

두 방식을 함께 보는 것은 ICH M7이 불순물 평가에 요구하는 방법이기도 합니다.

## 실행

```powershell
.\start.bat
```

`py -3.11`이 있어야 합니다. 처음 한 번은 `.venv`를 만들고 패키지를 내려받느라 몇 분 걸립니다. 준비가 끝나면 브라우저에 <http://localhost:8501>이 열립니다. 끌 때는 검은 창에서 Ctrl+C를 누릅니다.

같은 네트워크의 다른 컴퓨터도 쓰게 하려면 `share.bat`으로 띄웁니다. 스트림릿이 적어 주는 Network URL이 접속 주소입니다. 방화벽에서 8501 포트를 한 번 열어 줘야 하고, 로그인이 없으므로 그 망에 있는 사람은 누구나 들어옵니다. `start.bat`은 이 컴퓨터에서만 열립니다.

## 사용

1. 목표 물질을 고르거나 SMILES를 직접 넣습니다.
2. *생성 설정*에서 엔진을 고릅니다. AiZynthFinder는 이 컴퓨터에서만 돌고 키가 필요 없습니다. SynthEx는 LLM이 전략을 세우고 같은 AiZynthFinder로 탐색하므로 API 키가 있어야 하고 목표 구조가 외부 모델로 나갑니다.
3. **경로 생성**을 누릅니다. AiZynthFinder는 몇십 초, SynthEx는 몇 분 걸립니다.
4. 경로를 하나 고르면 탭 두 개가 나옵니다.

| 탭 | 내용 |
|---|---|
| 위험 검토 (ICH M7) | 경로의 단계와 물질 전부, 물질마다 어떤 판정을 왜 받았는지. *판정 사유와 원문*을 열면 반응마다 구조 그림과 SMILES가 나옵니다. *부산물 요청*도 여기 접혀 있습니다 |
| 독성 예측 툴 비교 | 도구를 골라 실행하면 같은 구조에 대한 도구별 판정, 점수 분포, 도구별 성능을 나란히 봅니다 |

1번 탭의 판정은 **ICH M7 규칙 하나**입니다. ICH M7은 규칙 기반과 통계 기반을 함께 쓰라고 요구하므로, 2번 탭이 나머지 절반입니다. 1번 탭만 보고 판단하면 한쪽만 본 것입니다.

경로는 우려가 적은 순으로 놓입니다. 빠진 경로와 그 이유는 *제외 기준과 빠진 경로*에 있고, 결과는 *저장*에서 JSON·HTML·CSV로 받습니다.

부산물은 누를 때만 공개 ASKCOS 서버로 나갑니다. 반응 하나씩 보내려면 *부산물 요청*을 열고, 경로 전체를 한 번에 받으려면 *생성 설정*의 **부산물 후보도 같이 받기**를 켠 다음 경로를 생성합니다. 기본은 꺼져 있습니다.

## 용어

식약처 ICH M7 번역본 표기를 그대로 씁니다.

| 용어 | 뜻 |
|---|---|
| 양성 | 변이원성이 있다고 본 것 |
| 음성 | 변이원성이 없다고 본 것 |
| 경고구조 | 변이원과 함께 자주 나타나는 부분 구조 |
| 경고구조 없음 | 걸린 구조가 없다는 뜻이지, 음성이라는 뜻이 아닙니다 |
| 상충된 결과 | 판단 범위 안이지만 결론이 갈린 것 |
| 예측 결과 없음 | 도구가 답하지 않았거나 실행이 실패한 것. 음성이 아닙니다 |
| 적용 범위 밖 | 모델이 판단할 근거를 갖지 못한 구조 |

## 성능

모델이 학습 과정에서 한 번도 보지 않은 구조 1,201종으로 모든 도구를 같은 조건에서 쟀습니다. 중간 수치와 측정 과정은 `evaluation/tool_benchmark_log.md`에 있습니다.

| 도구 | 예측 방식 | 균형 정확도 | 답한 비율 |
|---|---|---|---|
| 자체 모델 1 | 통계 모델 | 0.847 | 77.7% |
| 자체 모델 2 | 통계 모델 | 0.789 | 100% |
| ADMET-AI 2.0.1 | 통계 모델 | 0.749 | 100% |
| Toxtree 3.1.0 | 부분 구조 대조 | 0.741 | 77.7% |
| EPA TEST 5.1.2 | 통계 모델 | 0.714 | 61.1% |
| OECD QSAR Toolbox 4.9 | 부분 구조 대조 | 0.701 | 94.0% |
| ICH M7 | 부분 구조 대조 | 0.661 | 100% |

ICH M7 규칙의 민감도는 0.552입니다. 실제 양성의 절반 가까이에 아무 표시도 남기지 않으므로, 1번 탭의 "경고구조 없음"을 음성으로 읽으면 안 됩니다.

모델 1은 분자지문과 기술자를 함께 써서 가장 정확하지만, 염·혼합물·무기물은 지문을 만들지 못해 답하지 않습니다. 그래서 답한 비율이 77.7%입니다. 모델 2는 기술자만 써서 그 구조들도 읽습니다. 미학습 1,201종 중 268개가 모델 1만 기권한 경우였고 모델 2가 그중 72.8%를 맞혔습니다. 둘 다 답한 933개에서는 94.2%가 같은 답이라, 모델 2의 쓸모는 겹치지 않는 영역에 있습니다.

점수를 내는 도구는 모두 0.50을 판정 기준선으로 씁니다. 학습 자료가 양성 쪽으로 30.2% 치우쳐 있었지만 학습 가중치로 보정해서, 선행 연구가 쓰는 기준선을 그대로 둘 수 있었습니다.

QSAR Toolbox는 균형 정확도가 Toxtree보다 낮습니다. 대신 특이도가 0.979로 가장 높고, 대조하는 구조 목록이 달라서 Toxtree가 놓치는 것을 잡습니다. 더 나은 도구라서가 아니라 다른 시각이라서 넣었습니다. 같은 Toolbox의 ISS 프로파일러는 Toxtree와 판정이 99.2% 일치해 사실상 같은 도구라 넣지 않았습니다.

## 별도 설치

용량이 커서 저장소에 넣지 않았습니다. 받자마자 쓸 수 있는 것은 자체 모델과 ICH M7 규칙입니다.

| 빠진 것 | 빠지면 |
|---|---|
| `external_tools/` (AiZynthFinder, Toxtree, EPA TEST, 모델 실행 환경) | 경로 생성과 외부 도구 비교를 못 합니다 |
| ADMET-AI 가중치 | ADMET 칸이 "예측 결과 없음"이 됩니다 |
| OECD QSAR Toolbox 4.9 (무료, 내려받기 약 3 GB, 설치 후 약 13 GB) | Toolbox 칸이 "예측 결과 없음"이 됩니다 |

QSAR Toolbox는 설치해 두면 끝입니다. 도구를 고르면 앱이 알아서 로컬 API를 띄웁니다(약 13초). 이미 떠 있으면 그대로 씁니다. 구조는 `127.0.0.1` 밖으로 나가지 않습니다.

EPA TEST는 설치 폴더를 환경 변수 `EPA_TEST_HOME`에 적어 둬야 합니다. 비어 있으면 스크립트가 그 사실을 알리고 멈춥니다. 결과가 없는 것을 0으로 바꿔 내놓지 않습니다.

## 폴더

| 경로 | 내용 |
|---|---|
| `app/` | 화면과 판정 로직. 진입점은 `app.py` |
| `models/` | 학습된 모델 파일. `_balanced`가 쓰는 쪽이고, 가중치 없는 원본은 비교 기준으로 남겨 둔 것입니다 |
| `data/ames/` | 학습·검증·시험 분할 |
| `ames/` | 모델 학습 스크립트와 결과 |
| `evaluation/` | 도구 실행·비교 스크립트와 측정 결과 |
| `evaluation/tool_benchmark_log.md` | 측정 기록 원본. 수치의 출처는 전부 여기입니다 |
| `test/` | 단위 검사 |
| `docs/` | 설계안과 제출 보고서 |

저장소에 없는 것: `external_tools/`(외부 도구와 실행 환경), `test/models/`(AiZynthFinder 모델과 재고), `synthex/`(별도 관리하는 상위 체크아웃). 전부 용량 때문입니다.

## 검사

```powershell
.\.venv\Scripts\python.exe -m pip install -r test/requirements.txt
```

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s test -p "*_unit.py"
```

소프트웨어가 제대로 도는지 볼 뿐, 화학적 성능을 검증하지는 않습니다. Windows에서만 확인했습니다.

## 한계

- 안전성 판정이 아닙니다. 경고구조가 없어도, 음성이 나와도 안전하다고 볼 수 없습니다.
- 박테리아 변이원성(Ames) 하나만 봅니다. 유전독성의 나머지는 다루지 않습니다.
- 계산으로 찾은 경로는 실험으로 검증된 합성법이 아닙니다.
- 점수는 확률이 아니라 순위를 매기는 숫자입니다.
- 실패와 무응답은 미평가이지 음성이 아닙니다.
- 부산물 후보는 예측입니다. 얼마나 생기는지, 정제로 빠지는지 모르므로 경로를 빼지 않고 순위만 내립니다.
- ASKCOS에 물어보면 반응물과 생성물 구조가 외부 공개 서버로 나갑니다.
- 화면에 들어 있는 예제 입력은 시험용입니다.
