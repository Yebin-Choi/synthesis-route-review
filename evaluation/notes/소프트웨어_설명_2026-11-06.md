예빈이 11월 5일에 말한 네 가지를 기준으로 정리했다. 측정으로 확인한 것과 확인하지
못한 것을 섞지 않았다. 측정하지 않은 것은 측정하지 않았다고 적었다.

> **2026-11-07 갱신.** 기준선 부분은 바뀌었다. 자료가 양성 30.2%로 치우친 것을
> 기준선이 아니라 학습 가중치로 보정하고 두 모델을 다시 학습했다. 그래서 판정
> 기준선은 선행연구가 쓰는 0.50 그대로다. 아래 성능표는 새 학습본 기준이고,
> 0.25를 고른 이유를 설명하는 대목은 지난 기록으로 남겨 두었다. 측정은

> 적어야 계산이 되는 화면이라 소프트웨어가 모르는 것을 아는 것처럼 보였다.
> 이 문서에 그 화면을 설명한 대목이 남아 있다면 지난 기록이다

## 요약: 가장 중요한 세 가지

**하나.** 모델 정확도는 거의 올리지 못했다. 하이퍼파라미터를 정직하게 다시 골라도
차이가 흔들림보다 작았고, 특징 조합을 바꿔도 마찬가지였다. 대신 **판정 기준선이
틀려 있었다는 것을 찾아냈고, 그게 정확도 몇 점보다 큰 차이였다.** 기준선 0.50에서는
실제 양성 열 개 중 세 개 반을 놓치고 있었다. 0.25로 내리니 두 개만 놓친다.

**둘.** 여러 도구를 한 화면에 올려 보니 **도구마다 판정이 자주 갈린다.** 우리 모델
두 개끼리도 일곱 개 중 하나는 다르게 답한다. 그래서 소프트웨어가 "어느 쪽이 맞다"고
정하지 않고 전부 보여 주기로 한 선택이 결과적으로 맞았다. 억지로 하나로 합쳤으면
그 불일치가 숫자 하나 뒤로 숨었을 것이다.

**셋.** 화면에 보이는 숫자는 확률이 아니다. 지금 쓰는 모델에서 "0.287"이라고 표시된
구조 2,002개를 모아 보니 실제로는 0.350의 비율로 양성이었다. 어긋남이 크지는 않지만
**방향이 일정하다.** 낮은 구간에서는 실제보다 낮게, 높은 구간에서는 높게 표시한다.
순위를 매기는 점수로만 읽어야 한다.

## 1. 지금의 상황

### 소프트웨어가 하는 일

목표 물질을 넣으면 합성 경로를 만들고, 경로에 나오는 물질들의 유전독성을 여러 도구로
검사하고, 부산물을 예측하고, 투입량을 계산한다. 화면은 네 개의 탭이다.

| 탭 | 하는 일 |
|---|---|
| 위험 검토 | 고른 단계의 물질마다 규칙 검사 결과와 근거를 보여 준다 |
| 도구 비교 | 도구 여섯 개가 같은 물질에 뭐라고 했는지 나란히 보여 준다 |
| 투입량 | 목표 질량에서 거꾸로 반응물 투입량을 계산한다 |
| 부산물 | ASKCOS에 보내 부산물 후보를 받고 각 후보를 검사한다 |

### 지금 실제로 도는 것과 안 도는 것

2026-11-06에 직접 돌려서 확인했다.

| | 상태 |
|---|---|
| 자체 규칙 (ICH M7 목록 + 구조 경보) | 돈다 |
| 우리 모델 (XGBoost, 지문+기술자) | 돈다 |
| 우리 모델 (기술자만, 설명 가능) | 돈다 |
| ADMET-AI 2.0.1 | 돈다 |
| Toxtree 3.1.0.1851 | 돈다. Java 21로 실행 확인 |

| AiZynthFinder (경로 탐색) | **돈다.** 프로프라놀롤로 경로 10개를 33초에 냈다 |
| SynthEx (LLM 경로 생성) | API 키가 있어야 돈다. 키 없이는 버튼이 잠긴다 |
| 효소 억제 예측 (티로시나제·엘라스타아제) | 돈다. **누를 때만 돌아간다.** 한 번에 3.7초 걸려서 자동 실행을 뺐다 |

경로 생성이 되는 것을 2026-11-06에 확인하기 전까지는 경로가 필요한 화면을 열 방법이
없었다. 그래서
`app/preview_with_example.py`를 만들었다. 저장소에 이미 들어 있는 예시 경로를
불러온 상태로 앱을 띄우는 것이고, 앱 자체는 하나도 바꾸지 않는다.

```
cd app
streamlit run preview_with_example.py --server.port 8530
```

이걸로 네 탭을 전부 열어서 눈으로 확인했다. 발표에서 화면을 보여 줄 때도 이걸
쓰면 된다. 불러오는 경로는 저장소의 소프트웨어 시험용 예시이고 합성 제안이 아니다.

### 데이터

학습에 쓴 구조는 19,963개이고 그중 30.2%가 양성이다. 평가에는 학습에 안 쓴 독립
자료를 쓰는데, 파일에는 3,091개가 있지만 **그중 1,890개(61.1%)가 학습 자료와
겹친다.** 겹치는 것을 빼면 1,201개가 남고, 모든 도구를 그 1,201개에서만 잰다.

> 이 61.1%를 빼기 전에는 우리 모델이 균형 정확도 0.863으로 보였다. 빼고 나니
> 0.824다. **겹치는 것을 안 빼면 자기 숙제를 자기가 채점하는 셈이다.**

## 2. 모델 성능 향상 실험

### 해 본 것과 결과

| 실험 | 결과 | 쓸모 |
|---|---|---|
| 하이퍼파라미터 중첩 탐색 | XGBoost 0.9018 → 0.9060 (흔들림 ±0.0069) | **없다.** 차이가 흔들림보다 작다 |
| 랜덤포레스트 중첩 탐색 | 0.8911 → 0.8975 (흔들림 ±0.0077) | **없다.** 같은 이유 |
| 특징 조합 바꾸기 | 지문 2,048개를 빼도 0.002밖에 안 떨어진다 | 설명 가능한 모델의 근거가 됐다 |
| 분할 방식 비교 | 골격 분할 0.9018, 누출묶음 분할 0.9171 | 어느 숫자를 보고해야 하는지 정했다 |
| 골격 집단별 난이도 | 아조벤젠 0.723, 퀴놀린 0.766, 퓨란 0.970 | 측정했지만 **이유는 설명 못 했다** |
| 보정 확인 | 표시 점수와 실제 활성 비율이 어긋난다 | "확률 아님"을 화면에 적게 됐다 |
| **판정 기준선 재측정** | **0.50은 틀린 선이었다** | **이번 작업에서 제일 큰 수확** |

### 가장 큰 발견: 기준선 0.50이 틀렸다

묶음 교차검증 19,963개에서 기준선을 0.20부터 0.80까지 훑었다.

| 기준선 | 양성 중 찾아낸 비율 | 음성 중 음성으로 본 비율 | 균형 정확도 |
|---|---|---|---|
| 0.20 | 83.0% | 81.5% | 0.822 |
| **0.25** | **80.0%** | **84.8%** | **0.824** |
| 0.30 | 76.9% | 87.5% | 0.822 |
| 0.40 | 71.3% | 90.9% | 0.811 |
| 0.50 (쓰던 값) | 65.3% | 93.2% | 0.793 |
| 0.70 | 53.7% | 96.5% | 0.751 |

0.50은 그냥 관습이었다. 아무도 재 본 적이 없었다. **0.50에서는 실제 양성의 34.7%를
놓친다.** 유전독성 선별에서 양성을 놓치는 것과 헛경보를 내는 것은 값이 다르다.
놓치면 위험한 경로가 통과하고, 헛경보는 검토가 한 번 늘 뿐이다.

0.25로 내리면 음성을 양성이라고 부르는 비율이 6.8%에서 15.2%로 늘어난다. 그 값을
치르고 놓치는 양성을 34.7%에서 20.0%로 줄이는 선택이다.

**독립 자료 1,201개에서도 같은 방향이 나왔다.** 0.25에서 균형 정확도 0.841,
0.50에서 0.824다. 다만 기준선은 교차검증에서 골랐고 독립 자료는 확인에만 썼다.
독립 자료에서 제일 좋은 값은 0.30(0.850)이지만 그걸 고르면 **평가 자료를 보고 설정을
고르는 것**이 되므로 쓰지 않았다.

> **11-07 결론.** 기준선을 옮기는 대신 치우침을 학습 가중치에 넣었다. 그러자
> 균형점이 0.43으로 올라가 곡선 꼭대기가 평평해졌고(0.40과 0.50이 똑같이 0.847),
> 0.50에서 양성의 77.4%를 찾는다. 기준선을 옮겨 얻을 것이 거의 없어졌으므로
> 0.50을 쓴다. 위 0.25 논의는 가중치를 주기 전 기록이다.

### 설명 가능한 두 번째 모델

쓰던 모델은 왜 그렇게 판정했는지 말하지 못한다. 측정해 보니 **판정의 거의 전부를
이름 없는 지문 비트가 결정한다.** 에틸렌옥사이드의 경우 이름 있는 기술자 215개가
전부 합쳐서 +0.006밖에 기여하지 않았다.

그래서 기술자만 쓰는 모델을 따로 학습했다. 같은 교차검증, 같은 겹, 같은 구조에서
비교하면 이렇다.

| | 지문+기술자 (쓰는 모델) | 기술자만 (설명 가능) |
|---|---|---|
| AUC | 0.9015 | 0.8996 |
| 0.25에서 민감도 | 0.800 | 0.819 |
| 0.25에서 특이도 | 0.848 | 0.833 |
| 0.25에서 균형 정확도 | 0.824 | 0.826 |
| 설명 | 안 된다 | **된다** |
| 독립 자료에서 판정 비율 | 77.7% | **100%** |

**AUC 차이 0.0019.** 설명 가능한 모델을 쓰는 값이 사실상 0이다. 에틸렌옥사이드에
대해 이 모델은 1순위 이유로 `fr_epoxide`(에폭사이드 고리가 있음) +1.852를 내놓는다.

그런데 **두 모델의 판정은 86.4%만 일치한다.** 엇갈린 127개 중 지문 모델이 맞은 게
74개, 기술자 모델이 53개다. 어느 쪽이 맞다고 할 수준이 아니다. 그래서 둘 다 기본으로
켜 두고, 갈리는 물질을 사람이 보게 했다.

기술자 모델의 기준선도 자기 교차검증으로 따로 쟀다. **0.25가 나왔다.** 빌려 쓰던
값이 자기 균형점이기도 했던 셈이다. 값은 안 바뀌었지만 근거가 바뀌었다.

### 설명하지 못한 것

골격 집단마다 난이도가 크게 다르다. 아조벤젠 0.723, 퓨란 0.970으로 0.247 차이가
난다. 왜 그런지 네 가지 요인(집단 크기, 라벨 치우침, 집단 내부 유사도, 학습 자료와의
유사도)의 상관을 다 봤지만 **어느 것도 설명하지 못했고 부호도 예상과 반대였다.**

아조 결합이 체내에서 쪼개져 아민이 된다든가, 치환기 위치에 따라 활성이 달라진다든가
하는 화학적 설명은 가능하지만 **우리가 측정한 것이 아니다.** 보고서에는 "어렵다는
것은 측정됐고 이유는 설명되지 않았다"까지만 쓴다.

## 3. 여러 도구를 다루는 소프트웨어

### 설계

도구 여섯 개가 같은 물질에 뭐라고 했는지 표 하나에 나란히 놓는다. **소프트웨어는
어느 쪽이 맞는지 정하지 않는다.** 판단은 사람이 한다. 대신 판단할 근거로 각 도구가
같은 자료에서 실제로 얼마나 맞았는지를 표로 같이 보여 준다.

### 도구별 실측 성능 (독립 자료 1,201개, 전부 같은 행)

| 도구 | 방법 | 판정 기준선 | 민감도 | 특이도 | 균형 정확도 | 판정 비율 |
|---|---|---|---|---|---|---|
| **우리 모델 (XGBoost)** | 통계 | 0.50 | **0.774** | 0.921 | **0.847** | 0.777 |
| 우리 모델 (기술자만) | 통계 | 0.50 | 0.648 | 0.930 | 0.789 | **1.000** |
| ADMET-AI 2.0.1 | 통계 | 0.50 | 0.678 | 0.820 | 0.749 | 1.000 |
| Toxtree 3.1.0.1851 | 규칙 | 해당 없음 | 0.691 | 0.790 | 0.741 | 0.777 |
| EPA TEST 5.1.2 | 통계 | 도구 자체 판정 | 0.629 | 0.798 | 0.714 | 0.611 |
| 자체 규칙 (ICH M7) | 규칙 | 해당 없음 | 0.552 | 0.769 | 0.661 | 1.000 |

**판정 비율이 중요하다.** EPA TEST는 열 개 중 여섯 개꼴로만 답하고, Toxtree와 우리
XGBoost 모델은 여덟 개꼴로 답한다. 정확도가 높아도 자주 답하지 않으면 선별 도구로서는
그만큼 쓸모가 줄어든다. 나머지는 틀린 답이 아니라 답이 없는 것이고, 음성으로 세면
안 된다.

### 기준선은 도구마다 다르다

처음에는 기준선 하나를 모든 통계 도구에 적용했다. 그런데 **0.25는 ADMET-AI에는 틀린
선이었다.** ADMET-AI는 0.50에서 0.749, 0.25에서 0.700이다. 하나로 맞추면 어느
한쪽이 손해를 본다. 그래서 도구마다 측정으로 고른 기준선을 따로 두고, 하나로 맞추는
것은 사용자가 켜는 선택으로 옮겼다. 켜면 그 손해를 화면에 적는다.

### 찾아서 고친 버그

**EPA TEST를 우리 기준선으로 뒤집고 있었다.** 도구마다 기준선을 따로 두도록 고치면서
EPA TEST에는 "기준선 해당 없음"을 줬는데, 되돌림 경로가 그런 도구에 우리 모델의
0.25를 대신 적용하고 있었다.

실제로 돌려 보니 이랬다.

| 구조 | EPA의 값 | EPA 자신의 판정 | 우리가 0.25로 그으면 |
|---|---|---|---|
| 에탄올 | **−0.01** | 음성 | 음성 |
| 에틸렌옥사이드 | 0.79 | 양성 | 양성 |
| 니트로벤젠 | 0.37 | 음성 | **양성** |
| 아닐린 | 0.36 | 음성 | **양성** |
| 디메틸니트로소아민 | 0.30 | 음성 | **양성** |

**여섯 개 중 세 개에서 도구 자신의 판정을 뒤집고 있었다.** 그러면서 성능표에는
EPA TEST 자신의 판정으로 잰 수치를 보여 주고 있었다. 표와 화면이 다른 말을 하고
있었던 것이다.

에탄올 값이 −0.01인 것도 중요하다. EPA TEST의 값은 0과 1 사이에 갇혀 있지 않다.
그 숫자에 선을 긋는 것은 애초에 그 도구가 한 말과 다른 종류의 진술이다.

고쳤다. 이제 **EPA TEST 자신의 판정을 그대로 보고하고**, 우리 기준선이 없는 도구에는
아무 기준선도 넘기지 않는다.

### 부산물 신호는 제외가 아니라 감점이다 (2026-11-06 결정·구현)

2026-11-04 실측에서, 한 단계의 부산물 후보 11개 중 7개에 경보가 걸렸고 이것을 제외
사유로 쓰니 **경로 10개가 전부 사라졌다.** 검토할 경로가 하나도 없는 화면은 안전
결과를 준 것이 아니라 빈 화면을 준 것이다.

그래서 부산물에서 나온 신호는 **순위만 내리고 경로를 빼지 않는다.**

| 신호가 나온 곳 | 어떻게 되나 |
|---|---|
| 시약·중간체의 경보 | 설정에 따라 제외되거나 검토 필요 |
| **부산물 후보의 경보·모델 양성** | **검토 필요 + 감점. 절대 제외 안 됨** |
| 사용자가 직접 금지한 구조가 부산물로 나옴 | **그대로 제외** |

마지막 줄이 중요하다. 사용자가 이름을 적어 금지한 구조는 예측이 아니라 지시다.

**비대칭의 이유.** 시약과 중간체는 반응에 실제로 넣는 물질이다. 부산물 후보는
예측이고, 얼마나 생기는지도 정제로 없어지는지도 모른다.

**감점의 크기는 같다.** 부산물 경보는 같은 경보가 시약에 있을 때와 똑같이 2.0을
받는다. 구현 중에 한 번 틀렸다가 고쳤는데, 처음에는 "부산물에서 나왔다"는 표시에도
감점을 매겨 부산물이 시약보다 **더 큰** 감점(3.0)을 받았다. 감점을 깎아 주려다 두
번 매긴 셈이었다. 차이는 감점이 아니라 **뺄 수 있느냐**다.

**근거는 그대로 남는다.** 사유가 두 줄로 남아서, 무엇이 걸렸는지와 그것이 부산물에서
나왔다는 것이 둘 다 보인다. 부산물 탭에도 "이 경로는 빠지지 않고 순위가 내려갑니다"
라고 적는다.

### "경보 없음"은 음성이 아니다

Toxtree에서 파생된 ISS 문서가 직접 이렇게 적는다.

> "the 'No structural alert' flag is not equivalent to a negative prediction."

ICH M7 (Q)SAR 분석 논문도 판정을 양성 / 음성(적용 범위 안) / 보류 / 적용 범위 밖
네 가지로 나누고, 뒤의 둘은 음성이 아니라고 못 박는다.

**우리 측정이 이것을 뒷받침한다. 규칙 화면 민감도가 0.552다.** 실제 양성의 44.8%
에서 경보가 안 걸린다. 그걸 "음성"이라고 찍고 있었다.

그래서 **규칙 도구는 화면에 "경보 없음"으로 찍는다.** 통계 모델은 그대로 "음성"이다.
**내부 판정값과 경로 제외 정책은 안 바꿨다.** 민감도 0.552는 경보 없음을 음성으로
세어 낸 값이라, 판정 자체를 바꾸면 그 숫자의 뜻이 달라진다. 측정값은 하나도 안
움직였고 낱말만 바뀌었다.

## 4. 화면 정리

### 무엇이 문제였나

같은 판정이 화면마다 다르게 나왔다. 비교 화면에서는 색 칩, 모델 화면에서는 영어
코드 `excluded`, 다른 데서는 문장이었다. 읽는 사람이 화면마다 읽는 법을 새로 배워야
했다. 그게 제일 큰 원인이었다.

### 무엇을 했나

공통 표현 모듈 `app/ui_kit.py`를 만들고 화면 일곱 개를 거기에 맞췄다.

| 바꾼 것 | 왜 |
|---|---|
| 판정은 전부 색 칩 하나로 | 한 열을 눈으로 훑을 수 있다. 문장은 안 된다 |
| 칩마다 낱말을 넣음 | 색만으로 뜻을 전하지 않는다. 흑백 인쇄나 색각 이상에서도 읽힌다 |
| "판정 못함"에 이유를 붙임 | "경보 없음"과 "모르겠다"는 다른 말이고 안심되는 건 하나뿐이다 |
| 캡션 더미를 항목 표로 | 캡션 네 줄은 네 개의 혼잣말로 읽히고, 같은 넷이 표면 한 개의 기록으로 읽힌다 |
| 내부 표기 제거 | `success`, `endpoint=ames`, `routes / steps / materials` 같은 것을 걷어냈다 |
| 사유 코드를 접는 기록으로 | 없애지 않았다. 화면에서 내렸을 뿐이다 |
| 부산물 후보 목록 추가 | 전에는 요청 성공 여부만 알려 줬다 |
| 후보 점수 분포 그림 추가 | 1순위가 멀리 앞선 건지 수백 개가 한 칸에 몰린 건지는 순위표로 안 보인다 |

### 화면을 실제로 열어 보고 더 찾은 것

테스트만으로는 못 잡는 것이 있었다. 테스트는 "이 글자가 화면에 있는가"를 보지,
**있으면 안 되는 것**은 보지 않는다. 예시 경로로 네 탭을 직접 열어 보니 다섯 개가
나왔다.

| 찾은 것 | 고친 방법 |
|---|---|
| 사유 코드 `conditional_warning`, `prohibited_material`이 화면에 그대로 찍혔다 | 모든 코드에 한국어 라벨을 붙이고, 라벨 없는 코드는 "그 밖의 신호"로 바꿨다 |
| 기권 이유가 영어로 나왔다 | 저장 기록은 그대로 두고 화면에서만 한국어로 바꿨다 |
| 한계 문구에 `status=success`, `strict_alerts` 같은 내부 표기가 있었다 | 무슨 일이 있었는지를 말하는 문장으로 다시 썼다 |
| 조건부 경고 문장이 `secondary_amine_nitrite: `로 시작했다 | 코드는 기록에 남기고 문장 앞에서 뺐다 |
| 지표 라벨이 줄바꿈되어 숫자가 한 줄 아래로 내려갔다 | 라벨을 짧게 줄였다 |

그리고 버그를 하나 잡았다. 활성 예측 칩이 **"비활성"을 빨간색으로** 칠하고 있었다.
`"활성"이 들어 있는가`로 검사했는데 "비활성"에도 "활성"이 들어간다. 게다가 이건
억제제 예측이지 독성 판정이 아니라서 빨강·초록 자체가 맞지 않았다. 중립색으로 바꿨다.

`test/test_reason_codes_unit.py`를 새로 만들었다. 엔진이 낼 수 있는 사유 코드를
소스에서 읽어 전부 라벨이 있는지 검사하므로, 나중에 코드를 추가하면 라벨을 붙이기
전까지 테스트가 실패한다.

### 실제로 돌려 본 결과 하나

예시 경로의 물질 5개에 도구 4개를 돌렸더니 아질산나트륨 하나에서 셋이 갈렸다.

| 도구 | 판정 |
|---|---|
| 우리 모델 (XGBoost) | **판정 못함** (구조를 읽지 못함) |
| 우리 모델 (기술자만) | 음성 0.09 |
| ADMET-AI | **양성 0.92** |
| 자체 규칙 | 경보 없음 |

**이 한 줄에 설계가 다 들어 있다.** 소프트웨어는 어느 쪽도 고르지 않고, 기권을
음성으로 세지 않고, 규칙 도구는 음성이 아니라 "경보 없음"이라고 적는다.

### 근거로 삼은 것

기존 도구의 화면 규칙을 직접 조사했다. 원문을 읽어 확인한 것만 썼고, 확인 못 한
것은 선행연구.md 4-1절 끝에 "인용 금지" 목록으로 따로 모았다.

- **QMRF v1.2** 양식의 항목 순서를 모델 출처 패널에 적용했다. 못 채운 칸은 비워 두지
  않고 "이 검사에서는 하지 않음"이라고 적는다. 그게 양식이 요구하는 방식이다.
- **VEGA**는 적용도메인 지수가 0.85 초과면 높음, 0.75~0.85 보통, 0.75 미만 낮음이다.
  우리는 별 등급 대신 **그 구간에서 실제로 측정된 AUC를 그대로** 적는다.
- **WCAG 2.1 성공기준 1.4.1**: 색만으로 정보를 전달하지 않는다.
- **van der Bles 2019**: 직접 불확실성(판정 자체)과 간접 불확실성(근거 자료의 품질)을
  섞지 말고 화면의 다른 구역에 두라고 권한다.
- **ASKCOS·AiZynthFinder·IBM RXN** 공통 규칙: 점수를 "점수"라 부르지 않고 무엇을 잰
  건지 이름을 붙인다.

`evaluation/notes/화면_표현_규칙.html`에 판정 칩 전부와 비교표를 어두운 화면·밝은 화면으로
한 장에 그려 뒀다. 보고서에 넣기 좋다.

## 5. 속도와 직접 조작 점검 (2026-11-06 늦게)

### 앱에서 기다리던 3.7초를 없앴다

새 목표 물질을 넣을 때마다 **화면이 뜨기 전에 3.7초**를 기다렸다. 원인은 효소 억제
예측이었다. 한 줄짜리 곁다리 기능인데, 별도 프로세스를 띄워 sklearn과 rdkit을 새
인터프리터에서 불러오느라 그만큼 걸린다. 저장된 모델은 2 MB대라 모델 로딩이 아니라
프로세스 시작 비용이다.

조사했던 ASKCOS 규칙이 "비싼 계산은 요청할 때만"이고, 그대로 적용해 **누를 때만
돌아가는 버튼**으로 바꿨다. 같은 물질을 다시 보면 캐시가 걸려 즉시 뜬다.

전체 테스트도 **397초에서 323초**로 줄었다. 검토 흐름을 보는 테스트에서 효소 예측을
꺼둔 결과다. 그 테스트들은 **선택 사항인 효소 모델 파일이 깔려 있느냐에 따라 다르게
동작하고 있었는데**, 그 문제도 함께 없어졌다.

남은 느린 테스트는 실제 모델을 학습하거나 채점하는 것들이다(자료셋 학습 52초, 효소
모델 16초·8초). 진짜로 그만큼 걸리는 일이라 그대로 둔다.

### 앱을 직접 눌러 보며 찾은 결함 넷

읽을 수 없는 구조, 4096자 초과, 염(아세트산나트륨), ICH M7 목록 물질
(에피클로로히드린), 프로프라놀롤 실제 경로 생성까지 넣어 봤다. 대부분은 올바르게
동작했고 넷이 잘못이었다.

| 찾은 것 | 고친 방법 |
|---|---|
| **구조를 읽지 못한 목표물에도 효소 예측 버튼이 눌렸다.** 경로 생성과 독립 물질 검사는 이미 막혀 있었는데 이것만 빠져 있었다 | 읽히지 않는 구조에는 버튼을 내지 않는다 |
| 경로 생성 준비 확인이 첫 시도에 실패하며 **영어 메시지**가 떴다 | 생성 관련 오류 13종을 화면에서 한국어로 표시. 재시도로 풀리는 오류에는 "'다시 확인'을 누르면 대개 넘어갑니다"를 붙였다 |
| `applicability=unknown`이 한계 문구에 남아 있었다 | 말로 풀어 썼다 |
| **모델 한계 문구 14줄이 영어 그대로** 화면에 떴다 | 전부 한국어로. 저장 기록은 영어 그대로 둔다 |

> **첫 시도 준비 확인 실패는 원인을 확정하지 못했다.** 작업 프로세스의 `TMP`가 검사
> 대상 폴더 안을 가리키고 있어서 실행 중 만들어지는 임시 파일이 검사와 겹칠 수 있다는
> 데까지는 봤는데, **같은 조건에서 8번 반복해도 재현되지 않았다.** 재현하지 못한 것을
> 추측으로 고치지 않고 메시지와 안내까지만 손봤다.

### 한 번에 하나씩 찾는 것을 그만뒀다

이런 누출을 지금까지 **앱을 열어서 읽다가 하나씩** 찾았다. 다음 것을 못 찾는다는
보장은 그대로 남는다. 그래서 규칙을 검사로 바꿨다.

`test/test_screen_language_unit.py`가 화면 문구에서 내부 문자열의 모양을 찾는다.
`snake_case` 식별자, `key=value` 토큰, 그리고 모델 한계 문구가 전부 한국어로 옮겨져
있는지 본다. **번역에서 숫자가 빠지면 실패한다.** 0.50과 0.5는 같은 값으로 본다.

검사 자체가 제구실을 하는지도 함께 확인한다. 지금까지 실제로 샜던 네 가지를 넣으면
전부 걸리고, 정상 문구에는 걸리지 않는다. 그게 없으면 **아무것도 잡지 못하는 검사가
통과하는 것처럼 보일 수 있다.**

## 발표에서 조심할 것

**하나. TDC 리더보드와 나란히 놓으면 안 된다.** TDC 1위 ZairaChem이 0.871인데 우리는
0.9018이다. 하지만 **자료가 다르다.** TDC는 7,255개, 우리는 여러 출처를 합친
19,963개다. 비교하려면 TDC 7,255개를 그 분할로 받아 우리 파이프라인을 돌려야 하고,
아직 안 했다.

**둘. ADMET-AI를 이겼다는 말은 조건을 붙여야 한다.** 같은 독립 자료 1,201개에서
균형 정확도 0.841 대 0.749인 것은 맞다. 다만 **확인한 것은 우리 모델이 그 1,201개를
학습에 쓰지 않았다는 것뿐이다.** ADMET-AI와 EPA TEST가 그 구조들을 학습에 봤는지는
알 수 없다. 둘 다 공개 Ames 자료로 학습했을 가능성이 있고, 그렇다면 그쪽에 유리하게
기울어 있는 비교다. 그런데도 우리가 앞섰다는 점은 말할 수 있지만, "모델이 더 좋다"가
아니라 "이 자료에서 이렇게 나왔다"로 말해야 한다.

**셋. 새롭다고 말할 수 없는 것들이 있다.** 여러 도구를 병렬로 보여 주는 것(VEGA,
EPA TEST, ProTox), 역합성과 독성을 묶는 것(Tien 외), 설명 가능성(VenomPred) 모두
선행연구가 있다. 선행연구.md 0절에 정리해 뒀다. **남는 빈자리는 "통합하지 않고
불일치를 그대로 보여 주는 것"이고, 그것도 문헌에서 찾은 규칙이 아니라 우리가 정한
설계다.**

**넷. 측정하지 않은 것을 측정한 것처럼 말하면 안 된다.** 골격 집단별 난이도의 이유,
Cassano 2014가 평가한 모델 7개의 목록, Teitgen 논문의 수치는 전부 미확인이다.
